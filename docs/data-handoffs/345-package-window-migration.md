# Package date-window migration – source PR only

Tracks https://github.com/MartinMarzi/KiteCruiseScout/issues/345.
Martin requested source preparation/testing, not live execution. Nothing in this PR applies SQL,
changes inventory, runs a verifier or activates redirects. No historical migration is edited.

The new migration is generated by the official Supabase CLI 2.121.0. It compares the existing
package view's parsed definition to the current source baseline and requires security_invoker.
Unexpected columns, joins, predicates or security drift abort the transaction. On replacement,
all existing view options, columns/order/types, owner and grants are preserved. The cruise view,
underlying RLS, rows and grants are untouched. The date predicate retains valid month/season
windows through their ending month; exact/day and legacy-null rows remain future-only. Malformed,
infinite or unsupported-year bounds are omitted. Slot status/capacity, prices, rooms and disciplines
are unchanged; the app still hides unavailable slots and treats coarse windows as unconfirmed.

## Reproduce offline

```
pnpm install --frozen-lockfile --ignore-scripts --filter kitescout
node --import tsx --test test/offers/package-window-view.test.ts
```

PGlite 0.5.8 is a pinned dev-only dependency. Tests run the entire new migration against synthetic
view dependencies, including 30 calendar cases in three timezones and five active/type/identity
cases. Metadata checks cover columns/types/order, owner, ACL, security_invoker/security_barrier,
table RLS/ACL and service-role versus anon/authenticated access. Drift errors roll back atomically.
This fixture is not a complete Supabase schema or evidence of live permissions. No real credentials
or network calls are used by tests. CI has read-only repository permission and no service secrets.
